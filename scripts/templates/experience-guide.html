Connect Asana and Figma

Claude reads the ticket and the design through two connectors. Each person connects their own: authorise Asana and Figma in your Claude connector settings (or with /mcp in a terminal Claude Code), and sign in when asked. You also need access to the ticket in Asana and to the file in Figma.

Check both work before you build anything:

2

Make sure the Asana ticket has what Claude needs

  • The test ID {{ID}} in the ticket, so Claude can find it. The ticket ID, the branch name and the folder name are all the same.
  • The page it runs on, and which tool it is for: Dynamic Yield, Adobe Target or AB Tasty.
  • What each variation changes, in words.
  • A Figma link for every frame and state: mobile, desktop, open, closed.
  • The event list: the name of each event, when it fires and how often.

If something is missing Claude asks. It does not guess selectors, copy or events.

If you have the links, put them on this page so the prompts carry them (this rewrites the page):

Use the build-experience skill to build {{ID}}.

{{ASANA_LINE}}
{{FIGMA_LINE}}

Read the ticket with the Asana tools. For every frame and state, call get_design_context and get_variable_defs and use those exact values in the CSS. Do not work from screenshots. If the Figma tools are not available, stop and tell me.

The folders already exist in experiences/{{ID}}/. Build variation-1 (and variation-2 if the ticket has one) and the control. For the events, use a console.log only for now. Do not merge anything and do not open a pull request.

What Claude does, in this order:

  1. Reads the ticket (get_task, get_task_stories, get_attachments).
  2. Pulls the exact values from Figma for each frame and state: get_design_context for layout, spacing, sizes, text and colours, and get_variable_defs for the design's own tokens. This step is required.
  3. Opens the live page and inspects the real DOM before writing any selector.
  4. Writes variation-1/src/index.js, then styles.scss, then the behaviour, then the control.

How to check it used Figma properly. Each frame should show a get_design_context call and a get_variable_defs call. If you only see screenshots, say this:

SAY TO CLAUDE IF IT SKIPPED FIGMA
Stop. Call get_design_context and get_variable_defs for each Figma frame and rebuild the CSS from those numbers, not from a screenshot.
4

Test it in the browser while you build

TERMINAL
node test.js {{ID}} variation-1
node test.js {{ID}} control

This opens Chrome on the client's site, injects your code and CSS on every page load, and reloads when you save. The page's console prints in your terminal. If the experience runs on another host than the client site shown at the top, add the URL at the end: node test.js {{ID}} variation-1 https://...

Check:

  • The terminal shows no [page:error] lines.
  • It matches Figma at mobile and desktop widths.
  • Phone-only problems show up in Safari, not Chrome's phone mode, so check once in the iOS Simulator.
  • Pages the experience is not meant for are untouched.

Tell Claude what is wrong in plain words, and paste the terminal lines if there are any.

5

Add the events

While you build, each event is only a console.log. That is on purpose: the tracking push is different for every client, so Claude never writes it from memory.

When the experience works:

  1. Open the event generator app and generate the events for {{ID}}, with their segments.
  2. Copy them and paste them to Claude like this:
SAY TO CLAUDE
These are the events from the event generator for {{ID}}:

[paste them here]

Replace the console.log in logEvent with exactly this, in the variation and in the control: same keys, same casing, same labels and segments. The control uses its own label and the ECO segments from the generator. Only real user clicks may fire an event: if the experience itself clicks a button, check event.isTrusted so that click is ignored. Change nothing else.

What the labels and segments look like for {{ID}}:

WhereLabelSegment
Variation 1{{ID}} | (Variation 1) | <Event name>{{ID}}EV1<letter>
Variation 2{{ID}} | (Variation 2) | <Event name>{{ID}}EV2<letter>
Control{{ID}} | (Control Original) | <Event name>{{ID}}ECO<letter>

The generator's snippet is the source of truth. The letters are the same in the variation and the control.

Then check with node test.js: tick every event in the ticket's list, each one fires once per interaction, and the control sends the same events and leaves the page unchanged.

6

Clean up and build

SAY TO CLAUDE
Remove every console line from {{ID}}, in all folders. Then check there is no ${...} anywhere in the JS.
TERMINAL
npm run build:experience -- {{ID}}

Good result: no warnings, and for each folder a line saying which JS file and which CSS file to paste. The CSS is compiled to dist/{{ID}}/<folder>/styles.css. The build also writes a main.js. Ignore it: it is not what you paste.

7

Paste it into the testing tool

Into Dynamic Yield, Adobe Target or AB Tasty, paste exactly these two things for each variation:

  • The JS file as it is: experiences/{{ID}}/<folder>/src/index.js
  • The CSS file, if the folder has one: dist/{{ID}}/<folder>/styles.css

Nothing is bundled or changed for you. Dynamic Yield and Adobe Target do not support ${...}, and the file goes in exactly as written, so build strings with +.

Check the tool's preview, not only node test.js: the test run injects after the page has loaded, so it hides flicker. Previews can serve an older save for a few minutes, so reload and confirm you are on the latest.

Start another experience

New to the repo? Clone it first:

TERMINAL (ONCE)
git clone git@github.com:Conversio-CRO-dev/conversio-experiences.git
cd conversio-experiences
npm install

Then, for each new experience, replace <ID> with its test ID (the client's prefix must be in clients.json). The two links are optional, and fill in the new page's prompts:

TERMINAL
git fetch && git checkout --no-track -b <ID> origin/main
npm run scaffold -- <ID> --asana="<ticket link>" --figma="<frame link>"

Then open experiences/<ID>/guide.html in a browser. It is already filled in for that experience.

If something goes wrong

What you seeWhat to do
Claude says the Asana or Figma tools are not availableReconnect the connector (step 1), start a new Claude session, and run the check again. Do not let it carry on from a screenshot.
The scaffold says the prefix is unknownThe client is not in clients.json. Ask whoever maintains main to add the site, then start again.
Chrome will not openRun npm install again.
node test.js refuses the fileIt has an import or export. Experiences are plain JavaScript: write the helper in the file.
Nothing appears on the pageOpen DevTools (F12) and look at the console. The terminal also shows [page:error] lines.
The preview shows an older versionPreviews can lag after a save. Reload, or use the new preview link.
